# Two identifiability runs, and which one the submitted manuscript uses

`identifiability.csv` is the **three-seed** run. It is what the submitted manuscript
quotes, and it is kept as the live file so `src.audit_manuscript` validates the text as
submitted. A copy is also at `identifiability_3seed.csv`.

`identifiability_8seed.csv` is a later run of the same protocol at the same batch with
**eight** seeds, completed after submission. It is not yet reflected in any manuscript.

| configuration | 3 seeds (submitted) | 8 seeds |
|---|---|---|
| constant propensity | 36% | 56% |
| constrained branch | 44% | 68% |
| free propensity | 59% | 82% |
| no anchor | 24% | 30% |
| fit spread across configurations | 150 nats | 187 nats |
| capacity fit gain, constant to free | 57 nats | 77 nats |

**The conclusion is unchanged.** The claim in the manuscript is that the relative spread
of the recovered activity increases monotonically with the capacity of the observation
branch, and that more capacity buys a little fit for a lot of indeterminacy. Both runs
show that ordering, in relative *and* raw standard deviation. The eight-seed magnitudes
are uniformly larger, which is the expected direction: a standard deviation estimated
from three draws understates.

**Nothing in the submitted manuscript is incorrect.** It states "three random
initialisations" in Materials and Methods, and a dedicated paragraph, "Three seeds is
too few, and the diagnostic is in-sample by design", reports the limitation and notes
that a larger seed count "was attempted and not completed". The eight-seed run is the
completion of that attempt and it supports the claim.

## How to use this at revision

If a reviewer asks for more initialisations — a likely request given the paper flags the
weakness itself — the answer already exists. Switch the live file and update, together:

* the spreads in Results (section "Is the activity/detection split identified?");
* "three random initialisations" in Materials and Methods;
* the two nats figures in Results and Discussion;
* `fig5_identifiability`, regenerated by `python -m src.figures`;
* the seven pinned values in `src/audit_manuscript.py`.

```bash
cp results/identifiability_8seed.csv results/identifiability.csv
python -m src.figures            # redraws fig5 from the live file
python -m src.audit_manuscript   # will fail until the text is updated: that is the to-do list
```
